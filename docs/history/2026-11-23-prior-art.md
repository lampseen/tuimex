# Prior art: two terminal mail clients, reviewed 2026-11-23

> *Edited 2026-11-24, before this repository was published.* History files
> here are otherwise never changed. This one named two other projects and,
> for each weakness found in them, the file and the line. Those details are
> removed: the weaknesses are being reported to the projects' authors
> privately, and a public list would reach an attacker first. What remains is
> each class of flaw and the rule tuimex took from it. The owner keeps the
> original. ADR-052 is the record of this exception.

Two existing open-source terminal mail clients were reviewed before tuimex
was planned, first as something to build on and then as evidence. Neither
was adopted. This is what was found, as classes of flaw and not as an
account of either project, and which record or test each became.

They were references for behaviour; see PLAN §12.

How far to trust this: one client was read in full where security mattered,
and what is said below about a sanitiser was confirmed by running that
sanitiser against test HTML. The other was read statically, in part, and
never built.

## What a mail client can get wrong

Every row was seen in one of the two. Which one is not recorded here.

### Where a message can act on its reader

| Flaw | Why it matters | Became |
|---|---|---|
| Remote content loads by default | Opening a message tells its sender when and from where | ADR-008 |
| A remote-content blocker that matches strings | A leading space, an upper-case scheme, `@import`, an upper-case scheme inside `url()` and a CSS escape each walk through it | ADR-008; corpus files `remote-img-leading-space`, `remote-img-uppercase-scheme`, `css-import`, `css-uppercase-url`, `css-escaped-url` *(content)* |
| A fetch that does not check where it is going | Once images are allowed, a message can make the reader's machine request a loopback or private address | ADR-008 (no fetch) |
| A message's HTML written to a file as it came, and opened | The sender's script runs in the reader's real browser from a `file://` origin, and remote content loads | ADR-009; corpus files `script-in-html`, `event-handler`, `meta-refresh`, `form-action` assert the sealed copy *(content)* |
| HTML shown from a `file://` page with relative addresses left in | `src="/etc/hostname"` names a file on the reader's disk | ADR-009; corpus file `relative-src-local-file` *(content)* |
| Any URL scheme handed to the system's opener | A link runs whatever program handles its scheme | ADR-018; corpus files `link-scheme-ssh`, `link-scheme-file` *(content)* |

### Where the client's own files betray it

| Flaw | Why it matters | Became |
|---|---|---|
| Passwords in plain text in the config | Anything that can read the file has the mailbox | ADR-010 |
| Config, database and log created with the default mode | Other users of the machine can read them | ADR-011 |
| A config read from the current directory first | A cloned repository can carry one that points the client at another server | ADR-011 |
| Predictable files under the system temporary directory, written through symlinks, never removed | Another user can read a message or choose what gets overwritten | ADR-011 |

### Where an agent is trusted too far

| Flaw | Why it matters | Became |
|---|---|---|
| Permission checks that all return `true` | A policy that reads as one and decides nothing | ADR-016; the fence in CLAUDE.md against a function that returns `true` where a check belongs |
| A surface for scripts and agents that is on by default and can send and delete | A message that talks to the agent can act as the owner | ADR-016 |
| An attachment that cannot be read is dropped and the send reported as done | The caller believes something was sent that was not | ADR-016 (agent drafts carry no attachment); PLAN §6.4 |
| A delete reported as done before the server is asked. *Not tested.* | The caller is told about a change that may not have happened | ADR-016 (no such command) |

### Where mail is lost or sent wrongly

| Flaw | Why it matters | Became |
|---|---|---|
| An address that does not parse is dropped and the rest are sent to | The message goes out without one of its recipients | ADR-015 |
| Delete and move send a bare `EXPUNGE`; delete is permanent | Every message anyone marked deleted goes, not the one meant | ADR-014, ADR-015 |
| A flag change that never reaches the server | The mailbox differs between machines | ADR-014; M4's exit |
| UIDVALIDITY never read from the server | After a folder is rebuilt, old UIDs name other messages | ADR-014; M3's exit |

### Where it is merely hard to use or to change

| Observation | Became |
|---|---|
| `cid:` images never show: the sanitiser strips the scheme before the inliner looks for it | corpus file `inline-cid-image` *(content)* |
| A new connection and login for every operation; no IDLE | PLAN §4.3 |
| A config that does not parse is quietly replaced by defaults or a demo | PLAN §11 |
| The interface thread blocks on database and network work | ADR-006, ADR-001 |
| One application object that every part of the interface extends | ADR-001; ADR-004 |
| Unexplained `unwrap()` calls and discarded results in shipping code; every test module inline; no golden tests; no decision records, budgets or dependency policy | CLAUDE.md's fences |

## What a mail client can get right

Each of these was seen in one of the two as well, and tuimex follows it.

| Practice | In tuimex |
|---|---|
| Secrets in the keyring or from a command, zeroised, redacted in `Debug` | ADR-010, PLAN §4.5 |
| Files created 0600 with `create_new`, directories 0700 | ADR-011 |
| Remote images off by default | ADR-008 goes further: none |
| Only `http`, `https`, `mailto` open; deceptive links warn; tracking parameters removed; a labelled link shows its real URL first | ADR-018 |
| Known trackers named to the reader | PLAN §5 |
| UIDVALIDITY checked, CONDSTORE, IDLE, `UID MOVE`, `UID EXPUNGE` | ADR-014, ADR-023 |
| TLS that fails closed rather than falling back to plain text, for IMAP and SMTP | ADR-012 |
| A self-signed server's certificate is fetched, fingerprinted and pinned | ADR-012 |
| Delete moves to Trash; `u` undoes | ADR-015 |
| A send summary before sending; drafts saved while typing | ADR-015, PLAN §6.4 |
| Attachment names reduced to a base name; SQL parameterised | PLAN §5 (`attachment-path-traversal`); kept |
| Tests against a real mail server in CI | PLAN §9 |
| A fake server for unit tests | `FakeRemote`, at the trait rather than the socket |
| Storage, protocol, content and interface kept apart | ADR-001 |

## Tests this record asks for

Marked *content* above: these are the first entries in `tests/corpus/` and
M1's exit names them. The rest are named in the milestone that builds the
thing they test (M2: file modes; M3: UIDVALIDITY; M4: no bare `EXPUNGE`,
flags reach the server, no double send; M5: the grant table).

One more, from neither project and from the review itself: a message that
hides an instruction to an agent in an element a browser would not display
(`hidden-instruction`), which ADR-017 exists for.
